# LangchainRAG 产品方案（已审批定稿）

> 定稿日期：2026-10-07。本文件是全项目的"宪法"，所有开发以此为准。

## 一、目标

做一个**通过浏览器使用的企业级知识库问答系统**：把电商商品资料放进知识库，用户提问时 AI「先查资料、再回答」，并标注引用来源。开发框架使用 LangChain。

## 二、已拍板的决策

| 决定项 | 选择 |
|---|---|
| AI 大脑 | DeepSeek 云端 API（模型名 `deepseek-flash`，实施时用 /models 接口核实） |
| 浏览器界面 | Vue 3 + Element Plus |
| 数据库 | SQLite（账号、聊天记录）+ Chroma（资料向量） |
| 文字转向量 | 本地免费 BGE 中文模型 bge-large-zh-v1.5（1.3GB） |
| 检索精排 | 本地 bge-reranker-v2-m3（2.2GB） |
| 项目位置 | `E:\Vibe Coding\LangchainRAG项目` |
| 重型组件 | `F:\LangchainRAG-data`（虚拟环境约 8GB + 模型 3.5GB；E 盘放不下） |
| 演示品类 | 数码电子（耳机 / 手表 / 扫地机器人） |
| 开发方式 | 分 5 个里程碑推进，每个做完由项目决策人验收后再进下一个 |

## 三、系统工作流程

1. 网页把问题发给后端
2. 本地 BGE 模型把问题变成「数字 DNA」（向量）
3. 混合检索：向量检索 top20 + BM25 关键词检索 top20 → 去重融合 → 精排模型挑出最相关的 5 段
4. 「问题 + 5 段资料」发给 DeepSeek，指令：只根据资料回答、标注引用编号、资料没有就直说
5. SSE 流式推送：先发引用来源，再逐字推送答案（打字机效果）
6. 问答存入 SQLite（含引用快照），随时登录都能找回

## 四、功能需求与对应实现

| 需求 | 实现 |
|---|---|
| 浏览器管理知识库 | 管理员专属后台：知识库 CRUD、拖拽批量上传、处理进度、失败重试、重建索引 |
| 知识库问答+引用显示 | SSE 流式 + 引用卡片（含来源文件、原文片段，可展开） |
| 多用户多会话 | 每用户会话隔离，会话列表/改名/删除；数据全部持久化 |
| 历史对话找回 | SQLite 落库，换浏览器/重登录完整恢复 |
| 注册登录改密 | bcrypt 密码加密 + JWT 通行证 |
| 管理员 7Nanometer | 首次启动自动创建；管理界面后端每个接口独立鉴权（双保险） |
| 企业级优化 | 见下表 |
| 附加功能 | 点赞点踩、未命中兜底与清单、看板、导出、深浅主题、手机自适应 |

### 企业级优化清单

| 优化项 | 阶段 |

## 五、技术要点备忘（给开发者）

- LangChain 1.4.x：RAG 用 LCEL 写法（`{"context": retriever, "question": RunnablePassthrough()} | prompt | llm | parser`），不用已废弃的 RetrievalQA
- DeepSeek 走 `langchain-deepseek` 的 `ChatDeepSeek`；模型名如有变动改 `.env` 即生效
- Chroma 1.5.x：`PersistentClient` 单进程访问，uvicorn 固定单 worker，写操作加进程内锁
- BGE v1.5 系列查询侧必须加指令前缀「为这个句子生成表示以用于检索相关文章：」，否则召回率下降
- SSE 响应加 `X-Accel-Buffering: no` + 15 秒心跳注释
- 前端流式解析必须缓存"半行"（网络可能把一行数据切成两半）

## 六、里程碑与验收

详见 `docs/进度.md`（勾选制）。每个里程碑的"用户可见效果"：
- **M1**：浏览器能注册、登录、改密码；管理员见「管理后台」入口
- **M2**：管理员上传商品资料，看到「处理完成(n 段)」
- **M3**：提问 → 打字机答案 + 引用卡片；重登录历史全在
- **M4**：更准（混合检索+精排）、更懂（多轮指代）、更快（缓存秒回）、不瞎编（兜底）
- **M5**：看板、主题、手机自适应、备份、完整交付

## 七、风险预案（摘要）

- Python 3.13 若个别包不兼容 → 单包降级，最后手段换 3.12 虚拟环境
- 显存不足 → 自动回落 CPU（`MODEL_DEVICE=auto`）
- 模型下载慢 → ModelScope 断点续传（重跑 `2-下载模型.bat`）
- AI 费用失控 → 语义缓存 + 限流 + 回答长度上限
